## 一、适用范围与定位

### 1.1 适用对象

【强制】本规约适用于所有**以灵犀为中台能力、对外承载获客/展示/成交的触点系统**，包括但不限于：

- 独立站 / 品牌官网商城（如 SmartEva）
- 展会落地页、活动页（若接入灵犀线索/商品）
- 未来的小程序商城、门户插件等

【强制】触点系统**不是**灵犀八大子产品之一，而是**渠道触点层（Touchpoint Layer）**应用；不得在触点仓内再实现一套企业级 CRM / MDM / IAM。

### 1.2 定位一句话

> 灵犀 = 经营与数据中台；触点 = 买家侧体验与成交入口。触点消费灵犀能力，向灵犀回传线索与订单。

### 1.3 与《技术规约》关系

- 触点仓可独立仓库、独立发布节奏。
- 凡与灵犀交互的契约、安全、租户、事件、错误码与 HTTP 头，**以本规约 +《技术规约》为准**。
- 触点仓内部业务代码风格可保留自身《开发规约》，但不得与本规约冲突。

## 二、系统边界与权威数据

### 2.1 禁止事项

【强制】触点与灵犀之间：

| 禁止 | 说明 |
|------|------|
| 跨系统直连对方业务库 | 含只读 JDBC；仅允许经 OpenAPI / 事件 / MCP |
| 触点自建企业员工账密体系（长期） | B 端运营账号归 Casdoor；过渡期须备案并设下线时间 |
| 触点长期双写商品主档 | 主数据权威在灵犀；触点仅镜像 |
| 触点绕过 llm-gateway 散落保管多模型 Key（正式环境） | 过渡期例外须架构备案 |

### 2.2 权威源划分

| 数据 | 权威源 | 触点职责 |
|------|--------|----------|
| 商品 / SKU / 多语言 / 分类 / 上下架 | 灵犀数据中心（或运营中心商品域） | 本地镜像 + 展示缓存；带 `sourceId` / `sourceVersion` |
| 线索 / 客户 / 商机 | 灵犀业务运营中心 | 询盘、聊天意向、下单买家映射回传 |
| 站内访客账号、购物车、会话、浏览轨迹 | 触点 | 本地；可绑定灵犀 `contactId` / `customerId` |
| 订单交易单据 | **触点成交事实 + 同步灵犀** | 触点生成 `siteOrderId`；同步后灵犀存镜像并挂线索/客户 |
| 企业知识 / 话术 / 提示词 / 品牌公约 | 灵犀知识中心 / 配置中心 | 触点助手优先检索灵犀；站内 RAG 语料应来自同步商品与已授权知识 |
| 企业员工 / 站点运营角色 | 灵犀 Casdoor + Casbin | 管理后台 SSO |
| 数字资产（发信账号、社媒号等） | 灵犀数据中心 | 触点不持有通道资产权威 |

## 三、身份、租户与站点

### 3.1 租户与站点模型

【强制】每个独立站实例绑定：

| 标识 | 说明 |
|------|------|
| `tenantId` | 灵犀租户 ID |
| `siteId` | 触点站点 ID（租户下唯一） |
| `siteChannel` | 固定枚举：`storefront` / `landing` / `miniprogram` 等 |

【强制】所有触点 → 灵犀调用必须携带租户与站点上下文（见附录 HTTP 头）。

### 3.2 B 端（站点运营后台）

【强制】SmartEva `standalone-admin` 及同类后台：

- 登录走 **Casdoor OIDC**（灵犀统一 IdP）。
- 权限走 **Casbin**（站点运营角色，如 `site_admin` / `site_editor`）。
- 【禁止】长期维护与灵犀无关的第二套员工用户名密码表。

### 3.3 C 端（买家）

【推荐】一期保留触点自有买家注册登录（邮箱验证码 + 站内 JWT）。  
【强制】回传线索/订单时，须携带可关联字段（邮箱/手机/站内 userId），供灵犀建档或匹配联系人。  
【参考】二期可引入 Casdoor B2C 应用实现跨触点会员统一。

### 3.4 服务间认证

【强制】触点服务调灵犀开放 API：使用 Casdoor **M2M client_credentials**（或灵犀签发的站点客户端凭证）。  
【强制】灵犀调触点 Webhook：HMAC 签名 + 时间戳防重放；URL 白名单登记。

## 四、开放 API 与事件契约

### 4.1 同步调用（触点 → 灵犀）

【强制】经 **APISIX 开放 API 分区**（或等价网关），路径前缀建议：

```
/api/v1/open/site/**
```

【强制】最低能力集（P0）：

| 能力 | 方法（示例） | 说明 |
|------|--------------|------|
| 商品拉取/增量 | `GET /open/site/products` | 按 `updatedAt`/`version` 增量 |
| 创建线索 | `POST /open/site/leads` | 询盘、助手意向 |
| 订单回传 | `POST /open/site/orders` | 幂等键 = `siteId + siteOrderId` |
| 订单状态更新 | `PATCH /open/site/orders/{id}` | 支付成功/取消/退款 |
| 知识检索 | `POST /open/site/knowledge/search` | 带租户与知识权限 |
| 健康检查 | `GET /open/site/health` | 联通性 |

【强制】统一响应信封与灵犀一致：`{ code, message, data, traceId }`；成功 `code = 0` 或 `"0"`（开放分区对外统一为数字 `0`）。  
【强制】写操作带 `X-Idempotency-Key`。

### 4.2 事件（灵犀 → 触点）

【强制】商品等主数据变更通过领域事件或出站 Webhook 通知触点；触点消费须幂等。

| Topic / Webhook | 说明 |
|-----------------|------|
| `lx.mdata.product.upserted` | 商品创建/更新 |
| `lx.mdata.product.off_shelf` | 下架 |
| `lx.mdata.price.updated` | 价格变更 |
| `lx.site.config.updated` | 站点配置/品牌公约变更 |

【推荐】一期无 RocketMQ 消费能力时，可用灵犀 → 触点 HTTPS Webhook；二期触点侧上事件适配器。

### 4.3 触点 → 灵犀事件（可选）

| Topic | 说明 |
|-------|------|
| `lx.site.lead.created` | 站点线索已创建（若走事件而非同步 API） |
| `lx.site.order.created` | 站点订单创建 |
| `lx.site.order.paid` | 站点订单支付成功 |
| `lx.site.chat.intent` | 助手识别高意向（可选） |

## 五、主数据与订单回传

### 5.1 商品镜像

【强制】触点商品表至少包含：`tenant_id`、`site_id`、`source_product_id`、`source_version`、`synced_at`。  
【强制】冲突策略：以灵犀 `source_version` 为准；本地运营字段（SEO 文案微调等）不得覆盖权威字段，若允许扩展字段须名单制。

### 5.2 订单回传载荷（最小集）

```json
{
  "siteId": "site_xxx",
  "siteOrderId": "SE20260817001",
  "currency": "USD",
  "amountMinor": 19900,
  "buyer": { "email": "...", "name": "...", "phone": "..." },
  "items": [{ "sku": "...", "sourceProductId": "...", "qty": 1, "priceMinor": 19900 }],
  "paymentStatus": "paid",
  "paidAt": "2026-08-17T05:00:00Z",
  "sourceChannel": "storefront"
}
```

【强制】金额用最小货币单位整数；时间 UTC ISO8601。

### 5.3 线索回传

【强制】来源渠道标记为独立站/触点；尽量带商品上下文（浏览 SKU、会话摘要 ID）。

## 六、AI 协同（触点助手 × Agent Runtime）

| 角色 | 系统 | 职责 |
|------|------|------|
| 触点对话壳 | SmartEva Eva 等 | 买家侧多轮对话、导购、订单查询（站内权限内） |
| 经营/知识智能体 | 灵犀 Agent Runtime | 跨域工具、知识中心、经营技能 |
| 模型出口 | 灵犀 llm-gateway | 配额、审计、多模型路由 |

【强制】触点助手**禁止**直连灵犀业务库。  
【推荐】商品问答可用触点 pgvector，向量语料来自灵犀商品同步。  
【推荐】超出导购范围的经营问题，经开放技能调用灵犀 Runtime / 知识检索。  
【强制】高风险承诺（改价、折扣、履约保证）须人工确认或明确免责话术。

## 七、前端与工程基线

【强制】触点前端技术基线与灵犀对齐方向：

| 项 | 要求 |
|----|------|
| 语言 | TypeScript 5.7.x |
| UI 运行时 | React 19.x |
| 样式 | Tailwind CSS v4.x |
| 组件 | shadcn/ui（@base-ui/react）优先 |
| 包管理 | pnpm |

【推荐】Next.js：商城可用 15.5.x 或 16.x；**同一触点仓内管理端与商城主版本差不超过 1**；与灵犀工作台联调组件时优先 15.5.x。  
【强制】浏览器敏感配置仅用 `NEXT_PUBLIC_*` 暴露网关地址；密钥不下发前端。

## 八、安全、支付与存储

【强制】支付走**支付连接器**抽象（Stripe/PayPal/本地支付等）；商户密钥存 Vault；【禁止】前端持有商户密钥。  
【强制】对象存储走 MinIO/S3（或灵犀 file-svc 预签名）；【禁止】生产环境长期仅用本地磁盘作为唯一存储。  
【强制】出站 Webhook / 支付回调验签；入站限流按 `siteId` + 租户配额。  
【强制】日志脱敏：买家手机号、邮箱、Token 不得完整打印。

## 九、部署与中间件隔离

【强制】允许触点与灵犀共用宿主机 / Docker 网络中的 PostgreSQL、Redis，但必须：

- **独立 Database**（如 `smarteva` 与 `lingxi`），禁止共用业务 schema 互访。
- 账号权限最小化（触点账号不能读写灵犀业务库）。

【推荐】触点可继续 Nginx + systemd 轻量部署；灵犀中台按自身 K8s/模块化单体演进。  
【强制】环境变量与密钥分仓管理，禁止把灵犀生产密钥打进触点前端构建产物。

## 十、分期落地

| 阶段 | 目标 | 验收 |
|------|------|------|
| **P0** | 契约互通 | 开放 API 可拉商品、回传线索/订单；M2M 鉴权；租户+站点绑定 |
| **P1** | B 端身份统一 | 站点 Admin Casdoor SSO；下线独立员工账密（或只读遗留） |
| **P2** | 商品单向同步 | 灵犀变更驱动触点镜像；停止触点侧权威主档双写 |
| **P3** | AI 合流 | Eva 接知识检索/技能；LLM 走网关计量 |
| **P4** | 支付与存储对齐 | 真实支付连接器 + MinIO/S3 |

## 附录

### A. HTTP 头（触点专用补充）

在《技术规约》HTTP 头基础上，触点调用**额外强制**：

| Header | 说明 |
|--------|------|
| `X-Site-Id` | 站点 ID |
| `X-Site-Channel` | 触点类型，如 `storefront` |

M2M 场景：`Authorization: Bearer <client_credentials_token>`。

### B. 错误码

触点调用开放 API 时优先使用灵犀平台错误码。触点自身 API 若暴露给买家，错误码段建议自洽，但回传灵犀时转换为开放 API 约定码。  
灵犀侧为触点预留平台段：`03xxxx`（独立站/触点开放错误，见《技术规约》附录；**勿占用**已分配给业务运营中心-服务的 `23xxxx`）。

### C. SmartEva 对照清单（落地检查）

- [ ] 停止仅依赖「同机 Postgres」作为集成方式，改为 OpenAPI  
- [ ] Admin 接入 Casdoor  
- [ ] 商品主数据同步方向改为灵犀 → SmartEva  
- [ ] 订单/支付成功回传灵犀  
- [ ] Eva 经网关或开放技能访问知识/经营能力  
- [ ] mock-pay / 本地 uploads 纳入 P4 替换计划
