【强制】模块依赖只能单向：`app → domain ← infra`；跨模块只能依赖目标模块的 `api` 包。由ArchUnit在CI中强制校验。

【强制】所有依赖版本只在 `lingxi-dependencies` BOM中定义，业务模块禁止出现版本号。
【强制】禁止引入功能重复的同类组件（如同时引入Hutool和Guava的重复工具、两个JSON库）。

## 二、后端编码规约

### 2.1 语言与风格基线

【强制】以《阿里巴巴Java开发手册（泰山版）》为基线，配合以下补充：
- Java 17 LTS；记录类（record）用于不可变DTO；switch模式匹配可用于复杂分支
- 一个方法不超过80行；一个类不超过800行；超过即拆分
- 禁止魔法值，必须提取常量；常量类按模块内聚（如 `SalesConstants`）

### 2.2 统一响应体与异常

【强制】所有REST接口返回统一响应体（`lingxi-starter-core`提供，禁止自行定义）：

```json
{
  "code": 0,                  // 0=成功；非0见错误码分段表
  "message": "success",       // 面向开发者的英文描述；面向用户的提示走 i18n messageKey
  "messageKey": "common.success",
  "data": { },
  "traceId": "a1b2c3d4e5f6"   // 全链路追踪ID，必须回传
}
```

【强制】异常体系：业务异常一律抛 `BizException(ErrorCode)`，由全局异常处理器统一转响应体；禁止在Controller捕获异常后自行拼JSON；禁止吞异常（空catch）。

【强制】参数校验使用Jakarta Validation注解（`@NotNull/@Size/@Pattern`），DTO上声明，Controller加 `@Validated`。

### 2.3 领域与事务

【强制】聚合根用领域对象表达状态流转（商机阶段变更必须经领域方法 `opportunity.advanceTo(stage)`，禁止Service直接set字段）。
【强制】事务边界在应用服务层（`@Transactional`只出现在app层），事务内禁止调用外部HTTP/MQ发送（用事务消息或事务提交后钩子）。
【推荐】跨模块一致性优先用RocketMQ事务消息，不用Seata强一致（除报表类只读场景）。

### 2.4 并发与异步

【强制】线程池统一通过`ThreadPoolManager`创建（线程名：`lx-{模块}-{用途}-`），禁止直接`new Thread`或使用`Executors.newXxx`默认工厂。
【强制】分布式锁用Redisson封装的`@DistributedLock(key, waitTime)`，锁粒度到业务资源（如 `lock:customer:{tenantId}:{customerId}`），必须有超时时间。
【强制】定时任务统一注册XXL-Job，禁止应用内`@Scheduled`直连生产（dev环境例外）。

### 2.5 枚举与状态机

【强制】所有业务状态（线索状态、商机阶段、工单状态、任务状态）定义为枚举并集中管理；状态流转表（from→to）显式声明，非法流转抛异常。
【推荐】状态变更同时发出领域事件（见6.2）。

## 三、前端编码规约

### 3.1 技术栈与工程

【强制】前端技术栈：

| 层面 | 选型 | 版本约束 |
|------|------|---------|
| 框架 | Next.js 15.5（App Router）+ React 19 | 锁定 15.5.x，不跟随 latest |
| 语言 | TypeScript 5.7+（strict 模式） | 禁止 `any` 新增代码（复用第三方类型除外） |
| 样式 | Tailwind CSS v4 + tw-animate-css | 禁止内联 style 写布局样式；自定义动画走 tw-animate-css |
| UI 组件 | shadcn/ui（基于 @base-ui/react 无头组件）+ CVA + clsx + tailwind-merge | 统一使用 Base UI 版组件，禁止混入 Radix UI 版 |
| 表单 | react-hook-form + zod v4 + @hookform/resolvers | 校验 Schema 用 zod 定义，与后端 DTO Schema 对齐 |
| 图表 | recharts 3（数据图表）+ ECharts 5（地图/热力/复杂可视化） | 弃用 react-simple-maps（已停更且不兼容 React 19） |
| 状态 | Zustand（Client State）+ @tanstack/react-query（Server State） | 接口数据一律走 React Query，禁止存进 Zustand 再手动同步 |
| i18n | next-intl | 禁止硬编码中文文案（注释除外） |
| 通知 | sonner（Toast） | 统一通知出口 |
| 图标 | lucide-react | 禁止引入第二套图标库 |
| 主题 | next-themes（明暗主题切换） | CSS 变量驱动主题，禁止 JS 切换样式文件 |
| 包管理 | pnpm + Turborepo | workspace 协议 `workspace:*` 引用内部包 |

【强制】单一 Next.js 应用，**不做微前端**；8 个子产品为 App Router Route Groups，共享同一套登录态、权限、UI 规范和构建管线。

【强制】Server Component 优先：页面默认为 Server Component，仅在需要交互（useState/useEffect/事件绑定）时标记 `"use client"`；Server Component 内禁止使用 React hooks。

【强制】数据获取分层：
- Server Component 内用 `fetch` + Next.js `revalidate` 做 SSR/ISR 数据预取
- Client Component 内一律走 `@tanstack/react-query`（由 `lingxi-request` 统一封装 QueryClient 配置）
- 禁止在 Client Component 内用 `fetch` 直接调后端 API（跳过缓存/重试/错误处理）

【强制】环境变量前缀分层：
- `NEXT_PUBLIC_*` — 客户端可见（API Base URL、地图 Key 等）
- 无前缀 — 仅 Server Component / Route Handler 可见（通道密钥等）

### 3.2 路由分区规约

【强制】路由分区命名与子产品对应（见 1.2 命名表），分区为 Next.js Route Groups（括号目录，不影响 URL 路径）：
- `(workbench)` → URL `/`、`/dashboard`、`/tasks` 等
- `(biz)/market` → URL `/market/*`
- `(biz)/sales` → URL `/sales/*`
- `(decision)` → URL `/decision/*`
- `(platform)/config` → URL `/config/*`

【强制】每个路由分区有独立的 `layout.tsx`（页面骨架、面包屑、分区级权限守卫），分区间共享根 `layout.tsx`（全局导航、主题、Provider）。

【强制】分区级 Feature Toggle：路由段通过 `generateStaticParams` / 中间件做 Feature 开关判断，关闭的分区返回 404 或"功能未开通"页面；开关配置统一在 Nacos 管理。

【强制】跨分区跳转使用 Next.js 原生 `next/link` 或 `useRouter().push()`，携带业务上下文用 URL query param：
```
/sales/customer-detail?id={customerId}&from=workbench
```
禁止通过全局变量 / localStorage / Context 传业务对象跨页。

【强制】权限守卫：`src/middleware.ts` 统一做路由级鉴权（校验 Token + 判断路由权限码），未授权重定向登录页或 403 页面；按钮级权限见 3.3。

【强制】**子产品模块 manifest 约定**（单应用内的模块装配契约）：每个路由分区维护一份模块清单（`src/app/{分区}/module.config.ts`），登记路由前缀、菜单树（titleKey/path/permCode）、分区级权限码（如 `sal:access`）、Feature Toggle 开关码；菜单与权限码由配置中心下发，前端按权限码过滤渲染。新增子产品/模块 = 新增路由分区 + 注册 manifest + 登记权限资源，禁止绕过 manifest 私挂路由与菜单。

### 3.3 组件与状态

【强制】页面组件目录结构：
```
src/app/(biz)/sales/leads/
├── page.tsx                 # 页面（Server Component，做数据预取）
├── layout.tsx               # 页面骨架（可选）
├── components/              # 页面私有组件
│   ├── lead-table.tsx       # "use client"（交互组件）
│   └── lead-form.tsx
└── loading.tsx              # 流式加载 UI（可选）
```
可复用组件进 `packages/lingxi-ui/`。

【强制】`lingxi-ui` 业务组件库基于 shadcn/ui 封装，统一输出：
- `LxTable` — 列表表格（封装分页、排序、加载、空态、列设置），8 个子产品列表页必须使用
- `LxForm` — 表单（react-hook-form + zod + shadcn/ui Form 集成）
- `LxChart` — 图表（recharts/ECharts 统一封装，SSR 安全：`next/dynamic` 动态导入 + ssr:false）
- `LxPermission` — 权限控制组件（`<LxPermission code="sal:lead:assign">{children}</LxPermission>`），无权限不渲染
- `LxDrawer` / `LxDialog` — 抽屉/弹窗（客户360抽屉等跨分区复用）
- `LxPhoneInput` / `LxCurrencyInput` — 国际化输入组件

【强制】权限码使用：
- 路由级：`src/middleware.ts` 校验路由绑定的权限码
- 按钮级：`<LxPermission code="sal:lead:assign">` 组件包裹，或 `usePermission('sal:lead:assign')` hook 判断
- 权限码命名见 7.2

【强制】Server State（接口数据）统一用 `@tanstack/react-query`（由 `lingxi-request` 预设 QueryClient：缓存策略、错误统一 Toast、自动重试、请求/响应拦截器解包统一响应体）；Client State（UI 状态）用 Zustand；**禁止把接口数据存进 Zustand 再手动同步**。

【强制】图表组件 SSR 安全：recharts/ECharts 组件必须 `"use client"` + `next/dynamic(() => import(...), { ssr: false })` 动态导入，避免 Server Component 直接渲染 Canvas/SVG 导致水合错误。

【强制】表单校验 Schema 用 zod 定义，与后端 OpenAPI 生成的类型对齐（`lingxi-types` 包提供）；禁止前端手写 interface 代替 Schema 校验。

## 四、接口设计规约

### 4.1 RESTful规范

【强制】URL规范：

```
/{服务}/{资源复数}              资源集合
  POST   /api/v1/sales/leads                    创建线索
  GET    /api/v1/sales/leads                    分页查询（?pageNo=1&pageSize=20&keyword=）
  GET    /api/v1/sales/leads/{id}               详情
  PUT    /api/v1/sales/leads/{id}               全量更新
  PATCH  /api/v1/sales/leads/{id}               局部更新（推荐用于状态类操作的字段）
  POST   /api/v1/sales/leads/{id}/assignment    动作类：非CRUD操作用动词子资源
  DELETE /api/v1/sales/leads/{id}               删除（逻辑删除）
```

【强制】统一路径前缀 `/api/v1`，版本升级升路径版本（`/api/v2`），禁止header版本号。
【强制】资源名用kebab-case复数名词；动作类用 `POST /{资源}/{id}/{动词名词}`（如 `/emails/{id}/send`、`/campaigns/{id}/launch`）。
【强制】分页参数 `pageNo`（从1开始）/`pageSize`（默认20，最大200）；分页响应体 `{ list, total, pageNo, pageSize }`。
【强制】时间参数传输一律UTC ISO8601（`2026-08-15T08:30:00Z`）；金额传输一律**最小货币单位整型或字符串**（分为单位的整数），禁止浮点。

### 4.2 契约管理

【强制】API-First：先提交OpenAPI 3.0契约（`docs/contract/{模块}/{接口}.yaml`）评审通过后才能开发；契约变更需评审并在CHANGELOG注明兼容性影响。
【强制】跨模块调用（单体阶段Java Interface、拆分后Feign）签名必须与OpenAPI契约一致，CI用Pact做契约测试。
【强制】向后兼容原则：只加字段不删字段不改语义；废弃字段标记`@Deprecated`并保留≥2个版本周期；Breaking变更必须升版本路径。

### 4.3 幂等与限流

【强制】所有写操作（POST动作类）支持幂等键：请求头 `X-Idempotency-Key`（UUID），服务端按key+租户去重，有效期24小时。
【强制】开放API（第三方/智能体调用）走APISIX独立分区：租户级限流（默认100 QPS）+ 应用级配额，响应头回传 `X-RateLimit-*`。

## 五、数据库规约

### 5.1 命名与基础规范

【强制】表名：`{模块}_{业务实体}` 小写下划线，如 `sales_lead`、`sales_opportunity`、`mkt_campaign`、`kc_template`、`dc_customer`、`iam_user`。公共字段表名前缀 `sys_`。
【强制】字段名小写下划线；禁用数据库保留字；布尔语义字段用`is_`前缀（`is_deleted`、`is_active`），类型用 `BOOLEAN` 或 `SMALLINT`。
【强制】每表必备审计字段（MyBatis-Plus自动填充，禁止手工赋值）：

```sql
id            BIGINT       -- 雪花ID主键
tenant_id     BIGINT       -- 租户ID（全局表/字典表除外，白名单制）
created_by / created_at    -- 创建人/时间(UTC)
updated_by / updated_at    -- 更新人/时间(UTC)
is_deleted    SMALLINT     -- 逻辑删除标记，默认0
version       INT          -- 乐观锁，默认0
```

【强制】业务编码（客户编码CUS-、线索LEAD-等）作为唯一业务键列(`biz_code`)与主键并存，唯一索引 `(tenant_id, biz_code)`。
【强制】多语言字段（商品名、模板内容等）统一用 `JSONB`（`{"zh-CN":"...","en-US":"..."}`），跨域API传输必须带明确locale；查询用 `->>'{locale}'` 提取并按需建表达式索引。

### 5.2 索引与查询

【强制】唯一索引必须带tenant_id前缀（多租户隔离）；高频查询条件组合建联合索引，区分度高的列在前。
【强制】单表索引数≤5个；禁止在低区分度列（如status）单独建索引。
【强制】禁止`SELECT *`；大字段（TEXT/JSONB大对象）拆附表。
【强制】分页禁止跨页深翻（`LIMIT 20 OFFSET 100000`），用游标方式（`WHERE id > {lastId} ORDER BY id LIMIT 20`）；ES场景用search_after。
【推荐】单表数据量预估超2000万或写入超5000行/分钟时，设计期即规划归档或分区策略（PG原生分区表，线索行为类表按月分区）。

### 5.3 变更管理

【强制】所有DDL走Flyway版本化脚本（PostgreSQL方言）：`V{yyyyMMddHHmm}__{模块}_{描述}.sql`，合并主干后禁止修改已发布脚本，修正用新脚本。
【强制】DDL前向兼容三原则：只增列不删列、不修改列语义、删除列/表需两个版本周期（先标记废弃→下版本物理清理）。
【强制】大表变更（>500万行）必须有变更评审（锁表影响评估）；加列带默认值用惰性求值写法（PG 11+ `ADD COLUMN ... DEFAULT` 不重写表）；需要重建索引/回收空间用 `pg_repack`，禁止高峰期 `VACUUM FULL`（锁全表）。

### 5.4 多数据存储使用边界

| 存储 | 允许承载 | 禁止承载 |
|------|---------|---------|
| PostgreSQL | 业务事实、主数据、配置 | 行为明细流水、日志、分析聚合 |
| Redis | 缓存、会话、计数、锁、限流 | 需要持久化的业务数据（任何"Redis里存了就没有PostgreSQL备份"的数据） |
| Elasticsearch | 检索索引（可从PostgreSQL/事件重建） | 唯一权威数据源 |
| ClickHouse | 行为明细、分析宽表、聚合结果 | 在线事务、点查高频的OLTP场景 |
| MinIO | 文件与素材二进制 | 结构化业务数据 |
| Milvus | 向量（知识/话术/画像embedding） | 原文存储（原文在PostgreSQL/MinIO） |

【强制】缓存键规约：`lx:{模块}:{业务}:{tenant_id}:{标识}`，如 `lx:sales:cust:10086:88123`；必须设置过期时间（默认≤24h）或配套失效策略（领域事件驱动驱逐）。

## 六、子产品集成规约

### 6.1 通信方式选择

【强制】跨子产品通信只允许三种方式，按序选择：

| 场景 | 方式 | 示例 |
|------|------|------|
| 需要实时结果的读/简单写 | **同步API**（进程内Interface/Feign，走api包契约） | 销售域读客户主数据 |
| 业务状态流转通知、可异步处理 | **领域事件**（RocketMQ） | 线索创建→通知→分配 |
| 批量数据同步、分析管道 | **CDC/批量任务**（Debezium抓取PG WAL→Kafka→CH） | 行为数据入分析仓 |

【强制】域间同步API超时默认≤3s（AI调用、文件传输、导出除外，可单独标注放宽）；对幂等读可有限重试，写重试必须幂等。
【强制】禁止：跨模块直连他人数据库/Mapper；跨模块循环依赖；同步API链路超过3跳（A→B→C→D禁止，改为事件）；用前端串多个写接口充当跨域事务。

### 6.2 领域事件规约

【强制】事件Topic命名：`lx.{子产品前缀}.{实体}.{动作}`，如 `lx.sal.lead.created`、`lx.mkg.email.opened`、`lx.ac.agent.task.completed`。
【强制】触点相关 Topic 使用前缀 `lx.mdata.*`（主数据下行）与 `lx.site.*`（触点上行），示例：`lx.mdata.product.upserted`、`lx.site.order.created`、`lx.site.lead.created`（详见第十六章与《触点独立站集成规约》）。
【强制】事件体统一信封：

```json
{
  "eventId": "uuid",            // 全局唯一，消费端幂等键
  "eventVersion": 1,            // 事件Schema版本
  "occurredAt": "2026-08-15T08:30:00Z",
  "tenantId": 10086,
  "actorType": "AGENT",         // USER | AGENT | SYSTEM
  "actorId": "agent-sales-01",
  "payload": { },               // 领域数据，只放必要字段+实体ID
  "traceId": "..."
}
```

【强制】消费者必须幂等（按eventId去重表/Redis）；消费失败进重试队列，16次后进死信Topic `lx.dlq.{原topic}`并告警。
【强制】事件Schema向后兼容（只加字段）；破坏性变更升`eventVersion`并双写一个迁移周期。

### 6.3 主数据引用

【强制】跨子产品引用主数据（客户/商品/联系人/员工）只存`ID + 冗余展示字段（快照）`，展示字段仅用于列表展示，业务判断必须回源API取实时值。
【强制】主数据变更（客户合并、员工离职）由权威源发事件，引用方订阅更新冗余快照。

### 6.4 前端子产品集成

【强制】子产品间页面跳转携带业务上下文用统一URL规范：`/sales/customer-detail?id={customerId}&from=workbench`；使用 `next/link` 或 `useRouter().push()` 导航，禁止通过全局变量/localStorage传对象。
【强制】跨子产品能力复用（如在营销页打开客户360抽屉）通过 `lingxi-ui` 统一组件（`<LxDrawer>` + 业务组件）实现，业务数据通过 React Query 按需加载，无需跨应用通信总线。

### 6.5 连接器规约

【强制】邮件、WhatsApp、社媒、访客识别、客服渠道、支付、外部数据商、**独立站触点**等外部能力，统一抽象为**连接器接口**（send/receive、accountHealth、rateLimit、verifySignature、quota；触点另见 SiteConnector 扩展方法），经基础设施适配层实现；**禁止在业务代码中硬编码厂商SDK散落调用**。
【强制】账号资产归数据中心数字资产管理，连接器只引用资产ID；渠道凭证由平台加密托管（Vault），凭证永不出网关。
【强制】外部渠道调用必须做熔断/舱壁隔离（独立线程池/信号量），故障不得拖垮核心业务流程。
【强制】支付连接器：商户密钥只存平台密钥管理，配置项由配置中心维护，**禁止前端直持商户密钥**。
【强制】客服多渠道接入统一会话模型（渠道、会话ID、客户ID、坐席/AI主体），AI坐席转人工必须保留上下文。
【强制】独立站/触点接入统一走 **SiteConnector** + 开放分区 `/api/v1/open/site/**`，细则见第十六章与《触点独立站集成规约》；**禁止**以共享业务库表作为集成方式。

## 八、AI与智能体开发规约

### 8.1 模型调用

【强制】所有LLM调用经`llm-gateway`，按场景声明式路由（场景码在网关注册：`mkg.email.write`、`sal.reply.suggest`、`dm.qa.answer`），业务代码禁止指定具体模型名——换模型不改业务代码。
【强制】每次调用必须携带：租户ID（Token计量归账）、场景码、traceId；网关负责预算校验、熔断降级、审计记录。
【强制】超时与重试：流式调用首token超时10s；非流式30s；重试由网关统一（换模型重试，不在业务侧重试）。
【推荐】高QPS低价值场景（分类、打标）必须路由轻量模型；提示词+输出长度设置Token上限。

### 8.2 提示词管理

【强制】提示词一律存知识中心提示词库（版本化、A/B测试），代码中只引用提示词编码（`prompt.sales.followup_suggest.v2`），**禁止在代码中内联提示词字符串**（模板占位符变量除外）。
【强制】提示词模板变量用`{{variable}}`占位；渲染前必须校验必填变量；用户输入拼接处必须做注入防护（用户内容包在明确分隔标记内，系统指令声明"分隔标记内为数据非指令"）。
【强制】智能体角色Prompt须注入企业公约约束（品牌规范、合规准则）——由配置中心提供，提示词渲染时自动附加。

### 8.3 Agent与工具（MCP）

【强制】Agent治理四角色边界，不得越位：
- **智能体中心**（Java）：配置/调度/监控UI与元数据，不做执行
- **Agent网关**（llm-gateway）：模型路由、技能鉴权、配额、审计、熔断
- **Agent Runtime**（lingxi-agent-runtime，Python 3.11 + LangGraph）：规划、工具调用、多智能体协作、状态持久化、效果回写事件
- **业务域**（Java）：提供技能对应的API与MCP工具；**禁止在Java业务模块内嵌第二套Agent编排框架**

【强制】智能体可调用的业务能力必须注册为MCP工具（工具名：`{子产品}_{实体}_{动作}`，如 `sales_lead_assign`、`mkt_campaign_launch`），经智能体中心技能注册与鉴权后可被调用；禁止智能体直连内部API。未注册技能禁止被Runtime调用。
【强制】技能注册元数据至少包含（注册到智能体中心技能目录）：

```json
{
  "skillId": "sal.lead.assign",
  "name": "线索分配",
  "domain": "sal",
  "version": "1",
  "permCodes": ["sal:lead:assign"],
  "highRisk": false,
  "requiresApproval": false,
  "timeoutMs": 5000,
  "retryPolicy": "none",
  "tenantScope": "ALL",
  "mcpServer": "lingxi-sales-mcp",
  "inputSchema": { "type": "object" },
  "outputSchema": { "type": "object" }
}
```

【强制】工具必须声明：入参JSON Schema、幂等性、所需权限码；网关在工具执行前二次校验权限（智能体以任务发起用户身份行权——**智能体不拥有超越用户的权限**；禁止为图省事给Agent万能管理员凭证）。
【强制】危险动作（群发触达、商机变更、删除类）必须标记`requiresApproval=true`，走人工确认工作流（碳硅协同的产品化保障）；人工接管后必须可中断/取消在途自动动作。
【强制】每个智能体任务必须记录完整轨迹（输入、规划步骤、工具调用与结果、Token消耗、最终输出）到agent轨迹库，供智能体监控与效果评估。
【强制】Runtime与业务域交互只走三种通道：Agent网关（模型）、注册的MCP工具/受控API（业务能力，带用户与租户上下文）、领域事件（任务触发与效果回写）。

### 8.4 RAG与结构化输出

【强制】RAG检索必须带租户过滤与知识权限过滤（复用kc知识权限）；引用来源必须随结果返回（知识条目ID），前端可展示"依据"。
【强制】智能决策问答（NL2数据）：只允许生成受限查询计划（指标/维度/筛选的DSL），DSL白名单校验后翻译为查询API执行；**禁止LLM直接生成SQL执行**；查询自动继承提问者的数据权限。
【强制】AI生成内容对外发送前必须过内容安全检测（敏感词库+合规检测），命中即阻断并记录。

## 九、安全规约

### 9.1 认证与会话

【强制】统一认证基于 **Casdoor**（OIDC/OAuth2.1 授权服务器）：JWT（RS256签名，JWKS轮换）；Access Token 2h + Refresh Token 7d（可配置吊销）；SSO单点登录；智能体M2M调用用client_credentials，token与用户上下文绑定行权。**禁止**业务服务自建用户名密码表分叉登录（员工主数据在数据中心/user-svc，认证归Casdoor）。
【强制】权限策略引擎统一 **Casbin（jCasbin）**：功能权限（RBAC）+ 数据权限（行级）+ 字段权限由iam-svc的Casbin模型集中管理，业务服务经starter-security SDK调用决策API，**禁止各域私有ACL表另搞一套**。
【强制】密码存储BCrypt(cost≥10)；登录失败锁定（5次锁15分钟）；敏感操作（权限变更、通道配置）二次验证。

### 9.2 数据安全

【强制】分级：L1公开 / L2内部 / L3敏感（客户联系方式、沟通记录）/ L4高敏（凭证、密钥）。L3及以上：展示脱敏（邮箱/手机中间掩码，字段权限控制）、导出审批+水印、审计强制。
【强制】传输全程TLS1.2+；L4存储加密（Vault/KMS信封加密）；日志与消息队列中禁止出现明文凭证与完整敏感字段。
【强制】租户数据越权为P0级安全事故：每个对外API必须包含跨租户访问测试用例（用租户A的token访问租户B资源必须403）。

### 9.3 通道与外部集成安全

【强制】社媒/邮件/WhatsApp账号凭证由数据中心数字资产统一加密托管，业务侧经授权代理使用，凭证永不出网关。
【强制】所有出站Webhook/回调URL登记白名单；入站回调统一验签（HMAC）+ 时间戳防重放。
【强制】营销触达必须内置频控与退订（unsubscribe）机制，退订名单全局生效——合规是产品底线。

## 十、国际化规约

【强制】**时间**：数据库与API一律UTC；服务端展示格式化按"用户时区"或"客户时区"上下文；客户相关时间轴（沟通记录）按客户时区展示并标注时区。禁止`new Date()`直接格式化入库存本地时间。
【强制】**语言**：前后端所有面向用户的文案必须走i18n资源（前端 next-intl，后端messageKey）；禁止硬编码中文文案（注释除外）。语言包key规范：`{子产品}.{模块}.{位置}.{含义}`，如 `sales.lead.list.title`。next-intl 消息文件按子产品分区管理（`packages/lingxi-i18n/messages/{locale}/{subproduct}.json`），App Router 通过 `generateMetadata` + `getMessages` 注入。
【强制】**币种金额**：存储"金额（最小单位整数）+ 币种ISO4217代码 + 汇率快照"；报表换算用快照汇率；禁止float运算（用整数分或BigDecimal）。
【强制】**字符集**：全链路UTF-8（PostgreSQL `UTF8` 编码，`lc_ctype` 需支持中文排序）；用户姓名、公司名等字段排序按目标语言排序规则（`ICU COLLATION` 按需创建，如 `collate "zh-x-icu"`）。
【推荐】新功能开发即产出中英双语语言包；AI辅助翻译生成草稿+人工校对后入库。

## 十一、日志与可观测规约

### 11.1 日志

【强制】统一JSON结构化日志（Logback + logstash-encoder），必带字段：`timestamp(UTC)、level、service、traceId、tenantId、userId`。
【强制】日志级别使用：ERROR（需人处理）/ WARN（自动恢复但需关注）/ INFO（关键业务动作：状态变更、任务完成）/ DEBUG（仅dev）。生产禁止DEBUG。
【强制】日志脱敏：手机号、邮箱、凭证、Token按规则掩码；禁止打印完整请求体（大对象/敏感场景只打印摘要与ID）。
【强制】业务关键动作打点的统一格式：`BIZ|{模块}|{动作}|{实体类型}|{实体ID}|{结果}`，供审计与监控解析。

### 11.2 指标与链路

【强制】每个服务必须暴露：QPS、RT（P50/P95/P99）、错误率、JVM指标（Micrometer→Prometheus）；agent-runtime（Python）暴露同等口径指标（OpenTelemetry SDK→Prometheus，含任务吞吐/失败率/Token消耗）；通道服务额外：送达率/打开率/失败率；llm-gateway额外：Token消耗、各场景调用量与成功率。
【强制】traceId全链路贯通：网关生成 → HTTP header → MQ消息属性 → LLM调用（作为业务维度）；SkyWalking自动打点为默认。
【强制】告警分级与响应：P0（服务不可用/数据越权/发信通道中断）5分钟响应；P1（错误率>1%/队列积压）30分钟；P2（慢查询/磁盘水位）当日。

## 十二、测试规约

| 层级 | 要求 | 等级 |
|------|------|------|
| 单元测试 | 领域层核心逻辑（状态机、评分、规则）行覆盖率≥80%；用JUnit5+Mockito | 【强制】 |
| 契约测试 | 跨模块API与事件必须有Pact契约测试，契约变更CI双向校验 | 【强制】 |
| 集成测试 | 仓储与外部依赖用Testcontainers（真实PostgreSQL/Redis/ES/MQ容器）；Agent Runtime用本地LangGraph测试图+Mock MCP工具 | 【强制】 |

## 十三、版本管理与发布规约

### 13.1 Git规约

【强制】主仓库主干开发 + 短生命周期特性分支：`feature/{模块}-{描述}-{任务号}`、`fix/`、`hotfix/`；分支存活≤3天，≤400行diff（大需求拆分）。
【强制】Commit message格式：`{类型}({模块}): {描述}`，类型feat/fix/refactor/test/docs/chore；关联任务号。
【强制】合并需≥1名模块Owner评审 + CI全绿；主干随时可发布。
【强制】数据库变更脚本与代码同仓库同PR提交（Flyway目录），评审必须包含DDL影响评估。

### 13.2 版本与发布

【强制】语义化版本：服务版本 `MAJOR.MINOR.PATCH`（对外API兼容性对齐MAJOR）；前端单应用统一版本（随服务端主版本节奏发布）。
【强制】发布窗口：常规发布每周两次；通道类服务（邮件/WA）发布避开营销任务高峰（发布前检查在跑任务）；节日 freeze 期发布需审批。
【强制】发布 Checklist（缺一不可）：Flyway脚本已验证 → staging回归通过 → 灰度计划（按租户比例）→ 回滚预案（镜像回滚+DDL回滚）→ 观测面板值班人确认。
【强制】Feature Toggle：新模块/子产品上线默认开关关闭，按租户白名单灰度放量；开关及配置统一在Nacos管理并登记。

## 十五、附录：HTTP头约定

【强制】全站统一HTTP头约定（网关、服务间调用、前端请求、智能体工具调用同等遵守）：

| Header | 说明 |
|--------|------|
| `Authorization` | Bearer Access Token（Casdoor签发JWT） |
| `X-Tenant-Id` | 租户ID（网关校验与Token一致性后注入，服务内从TenantContext读取，禁止业务代码从请求参数取租户） |
| `X-Trace-Id` | 链路追踪ID（网关生成，全链路透传：HTTP→MQ消息属性→LLM调用） |
| `X-Idempotency-Key` | 写操作幂等键（UUID，见4.3） |
| `Accept-Language` | 用户语言（locale，与i18n资源对应） |
| `X-Timezone` | 用户时区（IANA时区名，可选，优先用户配置） |
| `X-Site-Id` | 触点站点 ID（开放分区 `/api/v1/open/site/**` 必填；网关校验站点↔租户绑定后注入） |
| `X-Site-Channel` | 触点类型，如 `storefront` / `landing`（开放分区必填） |

【强制】服务间与智能体调用必须透传 `X-Tenant-Id`、`X-Trace-Id`、用户身份上下文；缺失租户上下文的请求由拦截器直接拒绝。
【强制】触点开放调用必须同时携带合法 `X-Tenant-Id`、`X-Site-Id`、`X-Site-Channel`；站点与租户不匹配时返回 `030002`。

## 十六、触点/独立站集成规约（修订摘要）

本章为相对技术规约初版的**增补**。完整条款以《触点独立站集成规约 V1.0》为准；冲突时以该专规 + 本章【强制】项为准。

### 16.1 边界【强制】

1. 独立站等触点**独立仓库、独立发布**，不属于八大子产品代码树。
2. **禁止**触点与灵犀业务库互访（含只读）；**禁止**共享业务 Schema；允许同集群中间件但 **Database 必须隔离**。
3. 主数据（商品/客户等）权威在灵犀；触点仅存镜像（`sourceId` + `sourceVersion`）。
4. B 端运营账号统一 Casdoor + Casbin；C 端买家账号一期可留在触点本地。

### 16.2 接入方式【强制】

| 能力 | 约定 |
|------|------|
| 同步 API | `/api/v1/open/site/**`，经 APISIX 开放分区 |
| 异步同步 | 领域事件或出站 Webhook；触点消费幂等 |
| 连接器 | 平台侧 `SiteConnector`（注册、鉴权、限流、审计） |
| 认证 | 站点 M2M（client_credentials / 签名）+ 管理端 Casdoor SSO |

### 16.3 事件 Topic 示例【推荐】

| Topic / 事件名 | 方向 | 说明 |
|----------------|------|------|
| `lx.mdata.product.upserted` | 灵犀 → 触点 | 商品创建/更新 |
| `lx.mdata.product.off_shelf` | 灵犀 → 触点 | 商品下架 |
| `lx.mdata.price.updated` | 灵犀 → 触点 | 价格变更 |
| `lx.site.lead.created` | 触点 → 灵犀 | 站点线索（亦可同步 API） |
| `lx.site.order.created` | 触点 → 灵犀 | 订单创建回传 |
| `lx.site.order.paid` | 触点 → 灵犀 | 支付成功 |

### 16.4 AI 分工【强制】

- 触点助手（如 Eva）= 买家对话壳与站点内技能；**不得**直连业务库做经营编排。
- 企业知识检索与跨子产品经营智能体 = 灵犀 Agent Runtime / 知识中心；模型统一经 `llm-gateway`。

### 16.5 分期对齐【推荐】

P0 开放契约最小集 → P1 Admin Casdoor SSO → P2 商品单向同步 → P3 Eva↔Runtime 技能合流 → P4 支付/对象存储连接器对齐。
